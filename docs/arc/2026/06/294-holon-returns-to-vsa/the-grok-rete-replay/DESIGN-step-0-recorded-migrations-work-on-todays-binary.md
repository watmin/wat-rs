# DESIGN — step 0: every recorded migration works on TODAY's binary

Branch: `replay/grok-rete` (main `a3218644d` plus carried tooling). Floor 5373/5373, clippy 0.
Ruling: `SEAM.md` § "RULED 2026-09-12".

## Why

The replay converts each grok-rete commit's `.wat` into main's syntax by running main's recorded
migrations over its before and after versions. That works only if the migrations work on today's
binary. **Measured, they do not:**

- **11 grep-rules codemods (40 rules, chain steps 1 and 3–12) match nothing.** Since `0b5742cc7`,
  `wat/grep.wat:239` folds every `Named` name (`:wat::core::string::concat` becomes
  `wat.core.string/concat`).
  - The rules still compare the old spelling, find no match, and exit rc=0.
  - The five that commit rewrote to folded literals do match, but they splice the folded name as
    old-text, and `fix-text-apply` refuses.
- **2 more (`to-faithful-clojure-net`, `-rete`) die with rc=2.** Main's rete fence now refuses a
  user fn in a `where` (`':fix::has-ns?' is not a rete primitive`).
- **No gate replays a recorded migration.** `tests/cli/grep_programs_still_match.rs` covers
  `wat-scripts/grep/` only, so all of this rotted silently.

## The contract decisions

**1. Rewriters join `Written`, readers join `Named`.** `Written` gains `text`, the verbatim
`ast-name` from before the fold. This finishes main's own split (`wat/grep.wat:79–86`):
*"`Named` says WHAT a node is called; `Written` says AND IT IS SPELLED HERE."* The consequences:
- A rewriting rule reads the spelling it rewrites.
- Its old-text is that spelling, so `fix-text-apply`'s claim check is real again.
- Reader-synthesized nodes are excluded, and so are string literals: a literal's span includes its
  quotes, so its width never equals its name's length.

**2. Every recorded migration in `wat-scripts/fixes/` (94) carries EITHER a replay fixture OR a
written exemption.** Nothing is exempt by silence.
- **A fixture** is `wat-scripts/fixes/replay/<stem>/before.pre` plus `after.post`, and optionally
  `stdin`. The gate asserts byte-exact output, idempotence, and non-vacuity.
- **The oracle (`after.post`) comes from HISTORY or from the codemod's header spec, NEVER from
  running the codemod.** A fixture generated by the tool under test proves nothing.
  - History: the `-`/`+` sides of a hunk the codemod's landing commit applied to a real file.
  - Every fixture also carries at least one near-miss line per rule, which must stay byte-identical.
- **A permanent exemption** is a header rune `;; rune:replay(unreadable-preimage) — <the reader's
  verbatim error>`. It is the ONE category, and it is for a migration FROM a grammar today's reader
  refuses to parse. Such a codemod can never run again, and the rune says so where it cannot be
  missed. Nothing else is exempt: a codemod that rotted is fixed, not exempted.
- **Temporary debt** lives in a `FROZEN_LEDGER` of stems, each named with its reason. It exists only
  between 0a and 0b.
  - A stale entry (the stem now has a fixture, or no longer exists) is red.
  - A stem with neither a fixture nor an entry is red.
  - 0b ends with the ledger EMPTY and the constant deleted.

**3. Every codemod declares its SCOPE** in a header line (`;; SCOPE: corpus` or `;; SCOPE: <glob> …`),
and the gate asserts the declaration is present. This lands in 0b, because writing each fixture means
reading each codemod anyway. The replay's step runner enforces it: it refuses a codemod with no
SCOPE, and it runs a codemod only over paths inside its scope. `fmt-head-fqdn-to-clojure` is the case
that motivates this: it rewrites any `":wat::…"` string, and it was written for 11 fmt and grep files.

## Rejected, with the four questions (Obvious / Simple / Honest / Good UX)

- **Rules match the folded name, and the emit side slices bytes plus asserts** — N / N / Y / N. Every
  rule would carry two spellings, and `fix-text-span-text`'s own doc calls slicing *"the WRONG door
  for a RENAME"*.
- **Replay each codemod on a binary from its own era** — Y / N / Y / N. It needs 28 binaries and
  leaves the tools dead on today's binary.
- **One new rename-table codemod** — Y / N / N / Y. It would be a third copy of the rename record,
  beside the 11 codemods and the partial `RETIREMENT_TABLE`.
- **Fixtures only for the 28 chain codemods** — Y / Y / N / Y. The other 66 could rot the same way,
  unseen. The builder ruled all 94.
- **Oracle = the codemod's own output** — Y / Y / N / N. It is vacuous.
