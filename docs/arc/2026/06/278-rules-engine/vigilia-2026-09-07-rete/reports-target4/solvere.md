## Findings

**F1 — Duplicated encoding: the fire-rules driver wrapper (CompileOutcome/FireOutcome match arms + fixed error text).**
- Braided concerns: test-harness *plumbing* (how to drive a fire-rules session and interpret its outcome) is re-encoded as a hand-typed wat-source literal inside 22 separate Rust functions, rather than expressed once.
- Where it should live: one shared builder, e.g. `fn drive_fired(inner_seed_expr: &str) -> String` (+ a `fn wrap_compile(build_rules_expr: &str) -> String`), in `mod.rs` alongside `render_phase_table`.
- Recommendation: introduce the abstraction; have all 22 sites call it.
- Judgment: **structural** — it recurs at every new cost/census file by copy-paste, and nothing ties the copies together; a change to `FireOutcome`'s variants or the assertion message would require 75 synchronized hand-edits with no compiler check.

**F2 — Duplicated encoding: the instrument-subtraction formula (`raw − pairs*cal_ns_per_pair`).**
- Braided concerns: the *"table which misreports its own instrument is worse than no table"* arithmetic that `render_phase_table`'s `net_of` (`mod.rs:546`) was written to centralize is independently reimplemented in `accum_cost.rs:698`, `fanout_cost.rs:425-427,558,730-732,828`, `strat_cost.rs:412`, `cascade_cost.rs:393,396`.
- Where it should live: a single `fn instrument_net(raw: f64, pairs: u64, cal: f64) -> f64` in `mod.rs`. The bespoke *table shapes* are legitimate composition (different diagnostic questions) and should stay separate; only the two-line arithmetic primitive should be shared.
- Judgment: **structural**, and sharper than F1 — the codebase's own comment names this exact risk as the reason the abstraction exists, and two of the files that partially adopt the abstraction (`accum_cost.rs`, `fanout_cost.rs`) still reintroduce the duplication in their other tests in the same file.
