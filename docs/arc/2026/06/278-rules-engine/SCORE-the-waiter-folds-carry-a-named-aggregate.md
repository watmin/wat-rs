⚠ **And both exemplars in my DESIGN were the wrong locus too**, which grok named exactly:

## ⛔ AND THEN I DERIVED A SECOND WRONG THING — which I probed instead of shipping

From grok's two refusals I reasoned: *"`:messages` types must cross a boundary; a `Peer` cannot
cross; therefore only stdlib can hold a Peer-carrying aggregate visible to a child."*

**Wrong.** Probed both halves:

```
defstruct in :messages holding a live Peer          →  "ok"
   + one field naming the generated Queue::Reply    →  S4c, verbatim
```

★★★ **A `:messages` type may hold a live `Peer`.** S4c was never about the Peer — it is *only*
about `box`, whose type `Vector<Directed<Queue::Reply>>` names `Queue::Reply`, a type
**generated** by `defsurface` rather than declared in `:messages`.

★ So the rule, stated precisely and now verified in both directions: **a type reaches an EmptyEnv
process child iff it is stdlib or declared in the surface's `:messages`** — `:fanout::Outcome`
(`circuit.wat:236`) is the live proof — **and a `:messages` declaration may name only `:messages`
types and stdlib.**

## ★★★★ GROK'S CANDIDATE 2 IS THE ANSWER, AND IT IS NOT A COMPROMISE

```wat
;; declared inside :queue::Queue's :messages, beside Waiter (sqs.wat:86)
(:wat::core::defstruct :queue::TakeAcc
  [store <- (:wat::kernel::Peer :- [:wat::query::Store::Op :wat::query::Store::Reply])
   keep  <- (:wat::core::PersistentVector :- [:queue::Waiter])
   calls <- :wat::core::i64])
```

`box` stays **outside**, as the second slot of a plain 2-tuple: `(Tuple TakeAcc box)`.

grok wrote that it *"does not kill nested construction."* It halves it — **two levels become one** —
and `wat/lint.wat:428` marks that as the readable floor: *"acc = Tuple(template, kwarg-names)"*,
**two is where a Tuple is still readable.**

★★★★★ **And it delivers the actual objective.** The point was never the fourth slot; it was that a
**fifth costs nothing**. `store-ns` becomes a named field on `TakeAcc` — no nesting, no paren depth
change, no re-balancing by trial. The edit that killed two strikes becomes ordinary.

⚠ Verified: `:queue::Waiter` is declared at `sqs.wat:86`, inside the `:messages` block (11 types),
so `keep` is legal there.
