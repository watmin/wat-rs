## ★ THE FINDING THAT MATTERS MOST — the purity fence is not the executable language

`NOTE-purity-fence-is-not-the-executable-language.md`. Five instances, **both directions**, all
reproduced by my own hand. The fence is a *syntactic purity walk*; it does not check macro-vs-primitive,
types-in-composition, or **totality**:

| form | fence | first fire |
|---|---|---|
| `cond` | **PASSES** | raises `UnknownFunction` — a macro; the `where` is quoted data and never expands |
| `(first ?t)`, some `?t = []` | **PASSES** | raises `MalformedForm`, **kills the fire — DATA-DEPENDENT** |
| `(Some ?k)` | **REJECTS** (located) | — a total pure constructor, refused; registry gap |

`first`-on-empty is the worst: compiles, fires correctly for a month, then one empty vector detonates
the whole fire. **No amount of green testing surfaces that.**

**It is the missing `total?` axis** — designed a month ago in `NOTE-overlay-read-path` Part 5 as
multi-tenant resource safety, never built. That framing understated it: this is a live correctness
hole in *first-party* rules. And note the designed axis is about **recursion/termination**, so **it
would not have caught this case** — `first` terminates fine, it is undefined on an input.

**The consequence for #49a:** its specification cannot be *"whatever the purity fence accepts."* That
set is neither sound (admits the unrunnable) nor complete (refuses the pure).

**The builder's ruling on the fix** (shape ruled, names NOT cast): rete-namespaced **total variants**
with a mandatory fallback — `(rete.i64// n 0 :else -1)`, `(rete/first n :else …)` — and the partial
forms disallowed in a `where`. It makes partiality *unrepresentable* rather than *provably-avoided*,
and it **dissolves the SQL fork**: with nothing able to raise, evaluation order stops being
observable, so #49a is free to reorder and index. OWED before building: the mint list (some totals
already exist — `PersistentVector/get`+`match`, `foldl` with a seed), **allow-list not deny-list**,
and an **intueri cast** for the names.

## What is TRUE and easy to get wrong

- **`fire-rules` → `fire-rules'` → the native Rust kernel.** `fire-rules-spec` is the oracle. I
  checked, because the naming invites the opposite guess.
- **`i64::mod` is FLOORED, sign of the divisor, clj-faithful** (`runtime.rs:4847`), validated 16/16 vs
  clojure 1.12.4 — it matches Clojure for **all** operands. A rider wrote the opposite into two file
  headers as a false constraint; corrected.
- **Generic `<` accepts an i64 var against an f64 literal; `f64::+` with an i64 arg is rejected.**
  Arithmetic refuses cross-type, comparison permits it silently. Verified by my own probes. **Unruled.**
- **`String/concat` is declared 2-arg, implemented variadic** — a 3-arg call is rejected by `--check`.
- **A raising predicate aborts the ENTIRE fire, on both engines.** Measured. So a compiled executor
  that "safely skips" a poisoned token would be unfaithful to both oracles.
- **`and`/`or` DO short-circuit** — proved by deleting a guard and watching the row die. #49a must
  preserve it, or reordering turns that row into a crash.
