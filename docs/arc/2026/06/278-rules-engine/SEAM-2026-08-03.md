## The rulings you inherit — do NOT re-litigate

1. **wat must never deadlock.** A service delivers state to the admin **when asked** — request/reply,
   never push. An unsolicited send blocks on a pipe nobody drains, and blocking at teardown is the
   deadlock. **Killed before the ask ⇒ nothing to ask** — an empty set, not lost data.
   ⇒ `ServiceEvent::Shutdown → nil` is **CORRECT**, there is **no race** to fix, and **no new
   `ServiceEvent` variant** is warranted. I framed all three as problems; the ruling dissolved them.
2. **Anything measuring PROCESS BEHAVIOUR is measured HERMETICALLY. Never modify the runtime to take a
   measurement.** *"the signal handlers were clear violators and caused unpredictable tests."*
3. **Non-stop signals are a bitflip eventually observed; stop must be dealt with.** Grounded:
   `request_kernel_stop` writes the wake pipe (wakes a blocked `poll`); `set_kernel_sigusr1` only sets
   a bit. So user signals are seen on the **next op**; only terminate wakes a blocked service.
4. **`signal` is on `Process`, never `Peer`** — a thread peer has no process to signal, so a `Peer`
   verb would be partial. Same reasoning as `i64::>` over generic `>`.
5. **Never `kill(pid)`** — `clone.rs:215-216` documents a pid as reuse-unsafe. Route through
   `Pidfd::send_signal`.
