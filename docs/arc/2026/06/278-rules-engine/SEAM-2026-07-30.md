The 18 `mutable_key_type` are ONE root and they are **false positives** — proven, not assumed. clippy
names the chain: `Value → Arc<SenderInner> → SenderInner → AtomicBool → UnsafeCell<u8>`. A channel
handle's closed-flag taints the whole enum. The hazard cannot occur because the interior-mutable
variants are exactly the non-atomizable ones: their `Hash` arms are `unreachable!()`, `PartialEq` uses
`Arc::ptr_eq`, and `is_atomizable` (`check.rs:1487`) rejects them from key positions.

**But that invariant has no gate**, and arc 216 says so itself
(`probe_arc216_stone5a_value_hash.rs:334`): the arms are *"verified by the doc-comment contract"*, which
it calls an **"honesty delta."** A convention plus a panic that fires after the mistake ships.

The stone builds the wall: `KeyEligibility::{Hashable, NeverAKey(reason)}` — a type in which
"interior-mutable AND hashable" **has no constructor**. `Value::type_name()` (`value.rs:1154`) is already
an exhaustive 46-arm match with no wildcard, so the forcing function exists; `key_eligibility()` is its
sibling and STOP-2 requires both come from ONE source. Two deliberate breaches required.

**The unlock that dissolves arc 216's skip:** it skipped because a `Sender` cannot be *constructed* at the
test layer. `is_atomizable` takes a **type-name path**, not a value — so the gate never constructs one.

**`clippy.toml`'s `ignore-interior-mutability` is deliberately NOT in that stone.** It is what the gate
earns; shipping them together lets the exemption land un-gated. Gate first, RED, then the config citing it.

## Lessons this session paid for (all three now in memory)

- **A grep that RETURNS hits is not an ENUMERATION.** Six times in one day: a count matching every struct
  in the tree; an identical `.kind` figure for three different types; "45 struct-update sites" that were
  pattern rest-syntax; a `StartupError` payload table truncated one line before the actual driver (cost a
  rider a STOP-2); literal counts 4× under; 151 diagnostics read as 151 sites. Ask what the tool counted.
- **A gate's NAME is where the lie lives.** I shipped `runtime_error_stays_narrow` asserting `<= 128`
  while clippy fires *at* 128. Renamed to `..._regression_bound` while that was true, renamed back when
  B2 made it true. D0 found three more tests that could not fail.
- **A filtered run is never a commit gate.** I committed and pushed on a 2-test `-E` filter; the floor was
  red. `-E` is a filter exactly as `grep` is.
