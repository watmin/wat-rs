## ⛔ The gate is dodged today, by spelling

The old gate checks the **exact** name `_` only (`src/check.rs:12487`: `if ident.as_str() == "_"`). **A
`_name` binding is a discard the gate cannot see.** A census build that also gated `_name` found **116
non-`nil` sites, 54 of them outcome values** (11 `SendOutcome`, ~40 `RecvOutcome`): the old gate's own
types, swallowed by a rename.

**Two are in the stdlib (verified):**

- `wat/telemetry/journal.wat` ~:95: `_es (Store/ensure-schema …)` → a `RecvOutcome`, never read;
- `wat/telemetry/span.wat` ~:98: `_w (Journal/write-logs …)` → a `RecvOutcome`, never read.

**The telemetry stdlib swallows its own failures.** That is a real bug, independent of which rule is
chosen.

## What an honest discard rule needs (measured, not ruled)

1. **What counts as a discard is structural, not spelled.** A binding that is **never read** is a discard,
   whatever its name. Keying on `_`/`_name` is the spelling root again.
2. **An explicit way to say "I intend to drop this"** for class (b). Options:
   - nil-returning twins (`print` already exists beside `write-string`);
   - a `for-each` for the `mapv`/`foldl`-for-effect idiom;
   - an explicit drop form. That one reopens the swallow door visibly, and **must not be allowed to drop a
     failure-carrying outcome**, or it is the escape hatch under a new name.
3. **A Never type** (or equivalent) for divergent forms (`assertion-failed!`, `eprintln`), so they don't
   read as an unresolved, droppable value.
4. The deftest harness's `do ~body` position, and the 27 tests whose contract is "a non-final `do` form may
   be anything".
